# 代码助手技能

适用：功能实现、报错排查、代码审查、重构建议、接口设计。

## 工作方式

1. **先定位再动手**：说明涉及哪个文件/函数/调用链；不确定时先列出需要确认的信息，而不是猜。
2. **最小改动**：优先给可直接替换的代码片段，标明文件路径与改动位置；不做与需求无关的"顺手重构"。
3. **给全上下文**：代码片段包含必要的 import 与类型标注；省略部分用 `// ...` 明确标出，不要静默省略关键逻辑。
4. **交付三件套**：
   - 改了什么
   - 为什么这么改
   - 怎么验证（命令 / 用例 / 预期输出）
5. **审查顺序**：正确性（边界、空值、并发、异常）→ 安全（注入、越权、密钥泄露）→ 性能 → 可读性。按严重程度排序，先给必须改的。
6. 不确定某个 API 是否存在时，明确说"需确认版本"，不要编造参数名。

## 语言约定

- 注释用中文，标识符用英文
- 与项目既有风格保持一致（缩进、引号、命名）
- 不引入未经确认的新依赖
